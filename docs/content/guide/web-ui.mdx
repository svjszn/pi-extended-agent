# Browser dashboard

The dashboard is part of the upcoming 2.0.0 release. It uses the same Pi engine,
profile, session format, tools, permissions, project trust and planning checks
as the terminal interface.

## Start the dashboard

Connect a provider using `/login` inside Pi, then run this from your project:

```sh
pi ui
```

The command starts a server on `127.0.0.1`, chooses a free port and opens the
printed address in your default browser. Keep that terminal running. **Ctrl+C**
stops the server and its Pi subprocess.

```sh
pi ui --port 3210
pi ui --no-open
pi ui --help
```

`--port` accepts 0–65535; 0 chooses a free port. `--no-open` is useful when
opening the address manually. Browser-launch failure leaves the server running
and prints a recovery instruction. The complete address includes a temporary
access token in its fragment. It authorizes access to your local chats; open
the complete URL in another tab rather than sharing it. The server does not
accept public bind addresses or cross-origin API requests.

## Find and continue a chat

The sidebar lists sessions from the active profile, normally `~/.pi/agent/`.
`PI_CODING_AGENT_DIR` selects a different profile. A configured
`PI_CODING_AGENT_SESSION_DIR` is also included. Search matches chat titles,
initial-message previews and project paths. Use the project filter to narrow
the list and **Refresh** to reload it. Theme selection is saved in your browser.

Selecting a chat first displays its stored conversation and then opens Pi in
the session's original working directory. The directory must still exist.
History viewing makes no changes; continuing uses Pi's normal session loading
and persistence. **Copy terminal command** copies `pi --resume SESSION_ID` so
you can continue in the terminal after closing the browser conversation.

The reader follows the selected branch, applies context edits, and includes
compaction and branch summaries. Custom policy entries and provider headers
are not exposed as conversation content. Image payloads are shown as attachment
notices; use Pi's terminal to inspect the images. Text is rendered as text and
a limited Markdown subset, never as HTML supplied by a chat.

Discovery is bounded to the latest 1,000 session files, 16 MiB per file and
128 MiB per scan. Damaged, unreadable, linked, newer-format or oversized sessions
are skipped with an on-screen notice. Refresh to pick up externally changed
files. Do not edit the same session from a terminal and browser simultaneously.

Browser transcripts retain up to 2,000 recent messages and about 2 MiB of text,
with 512,000 characters per message. Omitted content is marked explicitly; the
complete session remains on disk. These display limits never truncate a tool
confirmation: requests that cannot be reviewed completely are cancelled.

## Work with Pi

**New chat** starts in the directory where you launched `pi ui`; you can enter
another existing directory. An active chat's model, effort, permissions and
work mode carry into a new browser chat before it accepts any prompt. An
unrelated fresh dashboard start uses the normal defaults. Plan mode carries
over as a new draft, never as approval to execute an old plan.

Type a task and press **Enter** to send, or **Shift+Enter** for a newline. Replies
stream as they arrive. Expand reasoning or tool rows for details and use **Stop**
to abort the current run. Model choices come from Pi's available model catalog;
the effort menu contains only levels supported by that model. Changing models,
effort or permissions waits until the active run has finished.

The server runs one Pi process at a time. Another chat can be viewed while a
reply is running, but stop that reply before continuing elsewhere. Tabs share
this active process; a stale tab cannot send a prompt into a different chat.
After all tabs disconnect, a 10-second grace period allows reconnection before
the active request is aborted and pending dialogs are cancelled. Unsent drafts
are kept only in the tab's memory and are lost when it is reloaded or closed.

## Confirmations and questions

`ask` requires an explicit response for changes, shell commands and external
tools. The browser shows the complete RPC confirmation input in a scrollable
dialog. **Cancel** is the default; **Allow once** permits only that request.
`deny` retains the same reading/search-only restrictions as the terminal.
Subagents keep their own injected permission and planning guards.

`ask_user` opens a structured form with choices and written answers. Recommended
choices are labelled and never submitted automatically. Every question needs
an answer; **Send answers** returns validated results to Pi. Escape or Cancel
returns no partial answer. Questions and permission requests share the same
approval queue. Answers never grant permissions or approve plan execution.

Slash commands that work through RPC can be sent in the composer, including
`/permissions`, `/mode`, `/plan execute`, `/scout` and `/lens`. TUI-only screens
such as `/nano` and `/diff`, login flows, image uploads and terminal-only
selectors remain in the terminal. Keep using `pi update` for agent updates and
`pi update --engine` for engine updates; the dashboard does not install updates.

## Troubleshooting

- If no models are available, connect a provider with `/login` in Pi, then
  reopen the chat or refresh its model catalog.
- If a chat's directory moved, resolve its working directory through Pi's
  terminal session workflow before continuing it in the browser.
- If the engine cannot start, history remains readable; run `pi doctor` in a
  terminal and follow its recovery steps.
- If a port is occupied, choose another `--port` or omit the option.
- If a tab loses authorization, reopen the complete URL printed by the running
  `pi ui` command. A server restart issues a new token.
