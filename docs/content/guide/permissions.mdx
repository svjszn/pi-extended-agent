# Permissions

The names below apply from 1.5.0. Version 1.4.x uses `full`,
`ask`, and `read-only` for the same policies.

Fresh sessions use **Allow**. `/clear` and `/new` preserve your current
permission mode. To review changes and shell commands before they run, switch
to Ask mode:

```text
/permissions ask
```

Open `/permissions` without an argument to choose a mode interactively.

## Available Modes

| Mode | What the agent can do |
| --- | --- |
| `allow` | Run tools without approval prompts |
| `ask` | Read and search freely; request approval for changes, shell commands, and external tools |
| `deny` | Use built-in file reading and search; block changes, shell commands, and external tools |

The footer shows `allow mode`, `ask mode`, or `deny mode`. Your choice is
saved with the session and restored when you resume or reload it. Clearing the
conversation preserves that choice before extensions start. If the inherited
policy cannot be saved, tools stay blocked.

The previous names `full` and `read-only` remain accepted as command aliases and
in saved sessions, mapping to `allow` and `deny`. New selections are saved under
the new names. Deny still permits the built-in reading and search tools.

Memory reads and plan updates are available in all modes. Memory saves and
deletes require approval in Ask mode and are blocked in Deny mode.

## Approve an Action

The approval screen shows the tool, working directory, and complete input.
Long inputs use bounded pages: **PgUp/PgDn** switches pages, **Home/End** jumps
to the first/last page, and **Up/Down** scrolls within a page. The same review
applies to subagent approvals. Changing pages resets the selection to Deny.

Requests that cannot be displayed completely within 256,000 characters of JSON
are denied. Ask the agent to split the action into smaller calls. RPC clients
receive complete input within the same limit.

The default choice is **Deny**. Use Left/Right to select **Allow once**, then
Enter to confirm. Escape denies the action.

Each call needs its own approval. Changing mode or closing the session cancels
pending approvals. Tools that are already running continue under their
existing permissions.

## Scope

Permissions apply to agent tool calls, including calls made through other tools.
They are not an operating-system sandbox or a directory boundary.

Commands you enter explicitly with `!` or `!!`, slash-command actions such as
installing a skill, and code run directly by extensions keep their existing
behavior. Project trust is a separate Pi setting.

In print mode, actions that require approval are denied. RPC clients must
respond to the confirmation request.

[Plan mode](/guide/planning) blocks changes and shell commands even with
Allow until you approve execution.
