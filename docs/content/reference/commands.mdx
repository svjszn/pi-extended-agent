# Commands

## Inside Pi

| Command | Purpose |
| --- | --- |
| `/usage` | Available account usage limits for the active provider |
| `/stats` | Local activity calendar and history statistics |
| `/status` | Engine version, session ID, login, model, MCP metadata, and tools |
| `/doctor` | Read-only installation and session checks with recovery steps |
| `/diff [--staged] [path]` | Browse working-tree and staged Git changes |
| `/nano [path]` | Browse directories and edit existing text files in Pi |
| `/config` | Configuration overview and editable Preferences tab |
| `/context` | Context estimate, breakdown, and loaded resources |
| `/effort [level]` | Choose or directly set a supported reasoning level |
| `/theme [dark\|light]` | Choose a dark or light interface |
| `/color [default\|yellow\|green\|blue\|purple]` | Choose the accent for input borders, the Pi logo, activity charts, and subtle message backgrounds |
| `/permissions [mode]` | `allow`, `ask`, or `deny` |
| `/memory` | View, edit, delete, and toggle project memory |
| `/plan [goal]` | Start research, review a plan, and explicitly approve execution |
| `/mode [auto\|plan\|code]` | Select a work mode; code adds native codemode alongside ordinary tools |
| `/prompt [scope] [text]` | Preview instructions; edit session, project, or global additions |
| `/model [query]` | Search models, select one, or save a default |
| `/skills [query]` | Enable/disable installed skills with Space, search, preview, and install; close to apply changes |
| `/agents [run NAME TASK\|stop]` | Browse, create, edit, run, and stop subagents |
| `/scout TASK` | Research the codebase in a separate context |
| `/lens [TASK]` | Review current working-tree changes, or an explicit scope, in a separate context |
| `/clear` | Start a fresh conversation, keeping the model, effort, work mode, and permissions (`/new` does the same) |
| `/resume` | Search saved chats and continue a selected conversation |

Native Pi commands such as `/login`, `/logout`, `/new`, `/resume`, `/compact`,
`/reload`, and `/quit` remain available.

### Files and changes

`/diff` and `/nano` were added in 1.5.0. Both require an idle
interactive TUI. See [Files and changes](/guide/files) for navigation, saving,
supported files, and the distinction between manual edits and agent permissions.

### Memory actions

`/memory` accepts `list`, `read ID`, `edit ID`, `delete ID`, `add`, `on`, and `off`.

### Plan actions

`/plan` accepts `show`, `start`, `edit`, `execute`, and `cancel`. Other text is
treated as a new goal and starts a research task.

### Simplified command menu

The following commands are omitted and rejected when entered manually:

```text
/settings  /tree  /thinking  /scoped-models  /import  /export
/share  /bug  /copy  /session  /changelog  /hotkeys  /fork
/clone  /trust  /about-agent  /llama  /mcp
```

Use `/config` for preferences, `/effort` for reasoning, and `/status` for session
information. MCP management remains available through Pi's terminal CLI.

## In your terminal

```sh
pi
pi --continue
pi -r
pi --resume
pi --model PROVIDER/MODEL_ID
pi --tui-mode regular
pi --help
pi doctor
pi doctor --json
pi update
pi update --check
pi update --engine
pi update --engine --check
pi update --engine --rollback
```

`pi-extended-agent` is an alias for the same executable. Update options are
described in [Updates](/guide/updates).

### Diagnostics

Doctor was added in 1.5.0.

`/doctor` opens the shared command screen with OK, WARN and ERROR checks. It
inspects installation and engine files, profile access, settings JSON, and the
current session's model selection, permissions, project trust and saved plan.
It provides recovery steps and reports when the running engine differs from
the engine selected for the next launch.

`pi doctor` works before engine initialization, so it can diagnose a selected
engine that no longer starts. `pi doctor --json` emits a report with
`schemaVersion: 1`, check IDs/statuses and summary counts. Exit status is **0**
for OK/warnings, **1** for errors and **2** for invalid arguments.

Checks are local and read-only. No credentials, provider connections or engine
compatibility are tested, and no repair is applied. Credential files, model
configuration and session transcripts are not opened; setting values are
omitted, and the home directory is shortened to `~`. Settings file links are
reported without following them. Project settings are inspected only inside
a trusted active session. The standalone command does not inspect a live chat.
